## Law gaps (first concrete gap called out)

**First concrete gap: E3.3.** All three DSH folds expose only aggregate `event_count`/`source_event_count`; none emits source-event identities/ranges plus projector version. W10 cannot ask for an historical result and prove which exact source sequence produced each derived row. E3.2 has a narrower existing guard (domain validators are present), but the bridge metadata shadow and permissive TUI projections must remain subordinate.

## Cache deletion implications and W4.2 handoff

Safe characterization: deleting only the in-process `Session._view`, `WorkItem._snapshot`, or `CoordinationProjector._view` should slow reads and permit rebuild from their authoritative streams; it does not yet provide a shared contract or exact lineage. Unsafe deletion today: `session.json` (normal durable load rejects its absence), `_product_tool_completions` (bridge duplicate pairing is behaviorally consulted), or TodoStore's persisted state (it is the owner, not a disposable projection). W10's compare consumer therefore needs an explicit source sequence and projector version in its result before cache deletion can be used as an independent acceptance oracle.

W4.2 is bounded to three radically different designs only if a later caller/deletion test produces the missing common seam; otherwise resolve E3.12 as rejected and deepen the existing owners. In either case, preserve Work Item/Session/Todo semantic authority, add no Generation Runtime abstraction, and do not treat bridge/E4 projection records as product truth.
