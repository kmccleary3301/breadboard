# W6 FT-05 — Definition/compiler expressibility

## Scope and decision rule

This is a characterization of the current canonical product `HarnessDefinition` input and
`compile_harness_definition` only. **EXPRESSIBLE** means that the feature's author intent has a
closed, accepted Definition representation and survives compilation as effective configuration;
**PARTIAL** means that some intent is representable but a required identity, durability, or
runtime contract is absent; **INEXPRESSIBLE** means that the feature has no normative Definition
input. These verdicts do not claim that the current runtime implements the feature.

The canonical public Definition is a closed object (`additionalProperties: false`) with required
`schema_version`, `version`, `workspace`, `providers`, `modes`, and `loop`
([`contracts/public/schemas/bb.harness_definition.v1.schema.json:5-29`](../../../contracts/public/schemas/bb.harness_definition.v1.schema.json)).
The compiler resolves/merges/freezes that document
([`breadboard/product/harness/compile.py:191-197`](../../../breadboard/product/harness/compile.py)) and emits an effective graph plus explanation. Its runtime values deliberately exclude `extends` and `dossier`
([`breadboard/product/harness/compile.py:88-90`](../../../breadboard/product/harness/compile.py)); byte inputs supplied through `resource_inputs` become source-layer records with hashes, not feature records
([`breadboard/product/harness/compile.py:157-189`](../../../breadboard/product/harness/compile.py)).

## Non-goals and handoff boundary

No Definition schema, public event schema, or production code is changed by this report. W6 records
what can be authored today; W7.1 owns the durable-child runtime/replay cutover, and W11.1 owns
public annotation/sidecar (and any additional public Code Mode) contracts. Any later design must
keep compiler expressibility separate from runtime implementation and must not treat `dossier` or
raw resource bytes as a normative sidecar mechanism.
