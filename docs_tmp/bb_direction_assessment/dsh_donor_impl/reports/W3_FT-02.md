# W3.1 / FT-02 — generation and durable reconfiguration

## Verdict

Four cases reached terminal source-cause classifications on untouched ENGINE `main` `ad1fc39e7427c047dd9ff813297d4fecc9dc3032`. Existing owners correctly reject model-role edits during an active turn and durably restore a completed reconfiguration. Mid-turn reconfiguration and provider swap expose product gaps routed to `GEN-INTERNAL`: no quiescent trajectory boundary, premature publication, and inconsistent effective Lock identity after the provider swap.

The disposable probe exercised `SessionService.durable_reconfigure`, `SessionRunner.transition_product_session`, `Session.reconfigure`, `EffectiveHarnessLock`, `SessionRegistry`, and `session_store.load_session`. Controls passed: 3 focused model-role tests with 20 deselected; 2 rollback/kernel tests with 294 deselected. The probe, temporary roots, raw case JSON, and command transcript were deleted after extraction; only this report remains.

## Four cases

| Case | Classification | Owner evidence |
|---|---|---|
| Invalid edit during an in-flight turn | **COHERENT-REJECT** | `set_role` raised `ModelRoleResolutionError(code="model_role_transition_active_turn")`; the sole `session.started` event and Lock digest remained unchanged. |

## Evidence

All event identities came from the Product Session persistence owner. The bridge event list was empty because these fixtures emitted no streaming observation.

**Invalid in-flight edit.** Active turn marker `turn-inflight`; event identity remained `(invalid-inflight, 1, session.started)`. The Lock stayed `sha256:ff46ffa2d17c8551e5e61c214aac41fecc103310c25f0ef4b3d80bcc5cd335c2`. No publication or drain occurred.

**Mid-turn reconfiguration.** One admitted turn was deferred (`deferred_count=1`). Events were `(mid-turn, 1, session.started)` and `(mid-turn, 2, session.reconfigured)`. The Lock changed from `sha256:7fa1f2d7f55fa05e3664caad1ccee8fb79516a90e4a203da07e86305b73f77c3` to `sha256:ca4961779ff44f1500374dd9f6d116fff5e35f31572d37717f38b33eaf0374e9`. Session and turn admission remained open with no drain phase.

**Restart durability.** Events were `(restart, 1, session.started)` and `(restart, 2, session.reconfigured)`. A fresh process restored Lock `sha256:36f134e91a1162984684feb7b0babf99db4a498533db7d6948c4708a8d17138a3`, equal to the persisted reconfiguration event.

**Provider swap.** Events were `(provider-swap, 1, session.started)` and `(provider-swap, 2, session.reconfigured)`. The event applied `sha256:ea2126332d8936c6a1c96be7ad42f53b52e010dc3f40c73c510b17cedd0c5e42`; recomputation from the post-command runtime config produced `sha256:1bc305617d12ef0a7438c6c0015e8c4bb4fe394e49e358ac7f791e9f85e388c7`. The callback prepared a config before `active_model_role` became null, proving the two identities were assembled from different effective records.

## Handoff

FT-02 introduced no public event, schema, or API fact. `GEN-INTERNAL` must: (1) reject or coordinate adoption while a turn is active; (2) prepare the candidate before publication; (3) emit a durable trajectory segment boundary; (4) bind one canonical Lock identity to the effective runtime config; and (5) close admission before drain/teardown. W2.4 retains the named provider routes `mock/provider-a` and `mock/provider-b`; it must create fresh request observations rather than treating deleted characterization bytes as reusable evidence.
