# W2.3 / Provider provenance

## Verdict

Provider request provenance now remains an internal, secret-safe fact set at the existing request/profile, compiler, conductor, and invoker seams. No public schema, endpoint, SDK, or generic wrapper was added.

## Module card

- **Module:** provider request evidence and provenance
- **Workstream/node:** W2.3 / provenance
- **Interface:** `OpenAICompletionsProviderProfile.chat_request_provenance(messages, tools, requested_stream)`; `SystemPromptCompiler.compile_v2_prompts(...)["model_surface"]`; `ProviderInvoker._cache_observation(...)`
- **Hidden:** default materialization, adapter overrides, ordered prompt/tool source identities, cache-token alias normalization, and unknown-vs-observed cache state
- **Dependencies:** category 1 in-process profile/compiler/session facts; provider metrics remain the existing evidence sink
- **Adapters:** existing OpenAI Chat profile/runtime, existing structured-request recorder, and existing ProviderInvoker metrics collector
- **Callers:** `breadboard_engine.conductor.modes.get_model_response`; `OpenAICompletionsProviderProfile` callers remain unchanged; `OpenAIConductor` prompt compilation now retains the model-surface side facts
- **Deleted:** source-blind `SystemPromptCompiler._assemble` return path; it now returns ordered source contributions, eliminating a second prompt-order reconstruction in evidence consumers
- **Test surface:** `tests/providers/test_openai_profile.py::test_profile_request_provenance_separates_requested_default_and_adapter_facts`; `tests/test_prompt_compiler_v2.py::test_compile_v2_prompts_records_ordered_model_surface_contributions`; `tests/test_provider_invoker.py::test_provider_invoker_records_cache_observation_as_independent_facts`; `tests/test_provider_invoker.py::test_provider_invoker_requires_typed_operation_correlation_before_dispatch`

- **Public impact:** none

## Fact boundaries

`chat_request_provenance` labels each effective field as requested, default, effective, or adapter and carries an explicit orthogonal `uncertainty` value. Message/tool values are represented by canonical digests rather than copied content. The compiler records ordered prompt source references and content digests, ordered tool registry references and schema digests, and explicit uncertainty. Conductor structured-request evidence records those facts, model-history order, and immutable artifact URI/digest/size/media references without attaching resource bytes.

`ProviderInvoker` records cache read/write token observations, optional prefix digest, route/model, and a divergence reason when supplied. Missing provider cache tokens remain `None` with `observed=false`; no cache validity or behavioral relevance is inferred. Correlation is already typed at `_resolve_correlation` before runtime dispatch; its focused test records that existing law.

Already-covered and intentionally not duplicated: immutable `ArtifactRef` is the resource owner; media/tool-result conversion remains covered by `test_profile_wire_evidence_matches_media_and_tool_result_projection`; exchange lifecycle and normalization remain covered by existing ProviderExchange/Invoker tests.
