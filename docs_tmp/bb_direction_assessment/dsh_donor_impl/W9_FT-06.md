## Module card

- **Module / node:** `interface_inventory` / W9.1 / FT-06.
- **Interface:** `inventory(engine_root, tui_root) -> Inventory` and the equivalent CLI entry point. Inputs are existing ENGINE/TUI roots; traversal is sorted; output uses stable relative paths and sorted JSON keys; invalid roots/registries fail explicitly.
- **Hidden:** filesystem traversal, registry flattening, schema field extraction, static owner/event/export extraction, TUI token matching, compatibility/deletion candidate collection, and canonical serialization.
- **Dependencies / adapters:** standard-library parsing plus caller-owned filesystem roots (category 2 local-substitutable). No new port; the ENGINE and paired-TUI roots are two real input adapters to one inlined scanner.
- **Callers:** implementation supervisor and downstream W9 workstreams invoke the CLI; `tests/test_interface_inventory.py` exercises the Python seam and CLI. No existing production caller was migrated.
- **Deleted:** none. This is a new advisory capability; registries, owner symbols, generated bindings, and public contracts remain untouched.
- **Deletion test / non-deletion:** deleting the script loses the repeatable per-change inventory and recall proof, while deleting any registry or owner path would lose authority. Retain the script and its baseline/report/blind-spot evidence as durable tooling; expiry: none. The inventory remains advisory and never becomes an owner or merge gate.
- **Laws / public impact:** E2.11, E3.10; none.
